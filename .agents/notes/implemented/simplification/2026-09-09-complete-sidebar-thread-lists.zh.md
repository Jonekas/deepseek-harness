# Agent Note: 完整侧边栏线程列表

Status: implemented

[English](2026-09-09-complete-sidebar-thread-lists.md) | 中文

## 问题

五行上限把线程隐藏在反复点击展开其余的操作之后。请求完整线程列表的用户不需要在本来就能折叠的 Workspace 内再增加一种折叠机制。

## 决策

打开的 Workspace 分组渲染所有符合条件的 Session 行，包括新会话，不按数量截断，也不提供展开其余或收起列表的按钮。整个 Workspace 的折叠、单列表浏览、排序、搜索限制以及独立可折叠的已搁置区域保持不变。高于侧边栏的列表通过滚动浏览。

本决策部分取代 [Workspace 侧边栏顺序与折叠](../feature/2026-08-11-workspace-sidebar-order-and-folding.zh.md)中的折叠决策；其持久排序与浏览器本地视图所有权仍然有效。Session 拖拽锚点使用完整渲染分组，不再依赖隐藏剩余项的定位规则。

## 考虑过的替代方案

**保留更大的上限或持久化展开其余状态。** 两者都会保留第二种可见性状态，并在达到阈值或重置后隐藏行，与完整列表的要求相悖。

**同时移除整个 Workspace 的折叠。** 这会移除独立的分组导航能力，而它并非行数限制的一部分。

## 后果

每条符合条件的线程都能直接通过滚动到达。大型打开的 Workspace 会挂载更多行，并可能把其他分组推到视口下方；用户仍可折叠这些分组。重新引入上限需要新的用户需求，不能作为静默性能优化。Session 数据和 Host API 均不变。

## 验证

组件回归覆盖超过五行的列表、新会话变为非空白、重新打开分组、搜索结果显露和拖拽排序。所属 Web 场景断言完整列表且不存在溢出按钮；滚动条覆盖保留共享滚动容器和已搁置区域的位置。浏览器验收需要已授权的现有浏览器上下文或隔离测试 Host。
