# Agent Note: 移动端单视图外壳

Status: implemented

[English](2026-09-09-mobile-single-view-shell.md) | 中文

## Problem

外壳在任何宽度下都是三栏。手机上折叠的 56px 侧栏占用了阅读列所需的宽度，会话列表只能通过在对话之上展开侧栏才能到达，而输入框尾部分组（注入的用量胶囊加模型触发器）是 `flex: none`，其固有宽度把发送控件推出了卡片右缘。桌面窗口收窄到约 750px 以下时出现同样的溢出。记录区的内容宽度还有一个绝对的 680px 下限，一旦列比它更窄，这个宽度就不再描述它所在的列。

## Decision

`MOBILE_MAX_WIDTH`（768px，deepsuite MD 断点）是 `AppFrame` 不再作为分栏布局的宽度上界。三个占位者保持树中位置并保持挂载；侧栏与中栏共用一个整宽网格单元，由布局 store 的 `mobileView`（`'list' | 'chat'`）决定显示哪一个。隐藏用 `visibility` 而非 `display`，因此切换时滚动位置与草稿都保留。断点以下右栏永远不会占用轨道，拖拽手柄不渲染，侧栏也不会被要求绘制其折叠导轨。

返回路径由外壳自身拥有，因为列表不再与对话并排：一条 44px、带会话标题的返回条仅在对话视图中渲染。两个信号会打开该视图。打开**另一个**会话是导航手势，通过 `sessions.current` 观察；随会话列表恢复的选择只被记录为基线，因此重新加载停在列表。重新选中当前会话不会改变 id，因此侧栏列上的捕获阶段点击把落在 `[role="treeitem"][aria-selected]`（会话行，区别于工作区分组行的 `aria-expanded`）内的命中视为同一手势。

输入框的 `.trailing` 分组改为可收缩并在内部换行，`--dsh-chat-content-width` 的下限让位给比它更窄的列。

断点以下记录区是稀缺资源，因此其余每一条都要为自己的高度付费。对话头部去掉面包屑——被挤压时它们会省略成一个字符，而外壳自己的返回条已经写出了会话名——并收紧内边距、标签间距与标签下划线。输入框收紧卡片间距与控件行内边距，停靠状态的草稿降到一行下限。模型触发器直接取用其纯图标形态，而不等待 360px 的容器断点：在两个断点之间它的完整名称虽能放进该行，却会把其余控件挤到另一行。输入框下方的统计条被隐藏：两个胶囊在那里第一个词之后就被省略。返回条本身是一行 40px 的触控高度。

## Alternatives considered

**在对话之上做抽屉式浮层。** 它让对话保持挂载且可见，但手机上阅读整宽记录时，半遮的列表没有收益，而抽屉仍需要返回条提供的那个触发控件。

**把返回控件放进对话头部。** 头部左侧的插槽已被声明并占用（`conversation.session.header.lineage`），浮动控件会压在面包屑上。由外壳拥有一条返回条把改动收在一个包内，并找回头部在该宽度下丢弃的会话标题。

**只在 `sessions.current` 变化时切换视图，不用点击信号。** 它看不到对当前会话的重新选中，会把读者困在列表上。

**只修输入框溢出。** 那会留下导轨和到不了的列表，而这才是手机上的诉求，不只是一个渲染缺陷。

**让手机上的外围保持桌面密度。** 一个在 844px 屏幕上把 41% 交给各种条、头部、输入框与统计条的单视图框，其实并没有把屏幕交给记录区；正是切换到单视图，才让密度这个问题值得回答。

## Consequences

窄到无法容纳普通右栏的框现在就是移动端框：断点以上，折叠导轨总能留出右栏所需的 300px，因此 `canShow: false` 经由移动端下限而非 `computeColumns` 到达。回归钉住的可用性边界从 756px 移到了断点。`mobileView` 在双向跨越断点后仍然保留，因此两次收窄的桌面窗口会回到读者离开时的视图。点击信号跨包读取一个 ARIA 关系；会话行若失去 `aria-selected`，只会降级重新选中，普通的会话切换不受影响。

`ui-layout` 现在把 `@deepseek-ai/dsh-client-ui-primitives` 声明为开发依赖以取用返回控件的箭头图标；该包属于模块图基线外部件，不新增任何模块请求。

密度调整同时移动了四个包的手机呈现，因此改动其中任一条时都必须一并考虑其余：在 390x844 视口上，外围从约 350px 降到 245px，可见记录区从约 490px 增至 600px。有两项读数移到一次点击之后而非消失——模型名称（title 与无障碍名称不变）与输入框的轮次/token 统计。统计条仅由 CSS 规则隐藏，因此 `.root:has([data-composer-stats])` 仍能匹配，输入框保持其收紧后的底部留白。

## Verification

`ui-layout` 组件回归覆盖折叠后的呈现及其 owner 参数、断点以上分栏的恢复、对 `pending` 后 `ready` 会话列表的恢复选择基线、对两类行的重新选中点击、返回条的标题与回退，以及回到列表。Store 回归钉住默认视图，以及几何动作不会改写它。`pnpm run test:gui` 全绿，并在第二个 `dsh web` 实例上于 390/430px 与 769–1440px 的浏览器中实际验证了该框，且各条高度是实测所得而非从截图目测。
