# Agent Note: 会话删除——带保留期的移除与子代理级联

Status: implemented

[English](2026-09-07-session-deletion.md) | 中文

## 问题

harness 中没有任何途径可以删除会话。`SessionPersistence` 只提供 create、open、flush、stat 和 list；Workspace 注册表能用归档集把会话藏起来，却从不真正丢弃它；浏览器端只提供重命名、fork 和搁置。使用者确信再也不需要的会话会永远留在磁盘上，唯一的办法是手工找到它的目录。

搁置让这个问题更突出而非缓解：一旦线程可以被放到一边，被放置的那堆恰恰是完成的工作积累的地方，其中一部分值得彻底删除。

## 决策

删除成为行内菜单中的一等会话操作，位于带破坏性样式的确认框之后，并且移除持久化日志而非隐藏它。

- **`SessionPersistence.delete(id)`** 加入能力接缝：此后 `stat` 报告该会话不存在，`list` 不再列出它，`open` 抛出 not-found。契约允许后端在可寻址集合之外保留被移除的字节，但对其存活时间不作任何承诺，因此调用方必须把已完成的删除视为永久。
- **JSONL 后端以重命名实现删除**：把会话目录移入根下保留的 `_trash` 区域。单个根内的一次原子重命名意味着会话要么可寻址、要么被保留，绝不会停在递归删除可能留下的半擦除状态。`projectKey` 始终把 slug 包在 `--` 之间，因此这个保留名不可能与项目目录冲突；列举按名称跳过它——没有这一步，每个被删除的会话都会作为项目重新出现。
- **保留是恢复手段，不是特性。** 可配置的 `trashRetentionDays`（默认 30）限定它，每次删除会顺带丢弃过期条目。名称无法被本版本解析的条目绝不回收——操作者自己的副本不归后端处置。
- **重命名期间会声明写入所有权**，这既能以 `SessionAlreadyOwnedError` 拒绝在活动写入者之下删除，也能阻止写入者在移动过程中打开。
- **子代理后代随父会话一同删除。** 它们是拥有自身日志的会话，父会话消失后没有任何界面会列出它们，留下它们就会永远泄漏不可达的数据。血缘关系读自持久化头部，因此本进程从未加载过的后代也包含在内，而畸形的环不会让遍历空转。
- **fork 子会话绝不随行。** fork 会把继承的事件复制进自己的产物，因此删除任一侧都不影响另一侧的完整性。存活的头部可能指向已不存在的父会话，读取方本就容忍这一点。
- **在触碰任何成员之前先整体拒绝**：当会话或其后代正在运行时拒绝；部分删除的血缘比被拒绝更糟。
- **`ApiSessionAgentController` 现在保留它创建的 `AgentHandle`。** 此前它取走 `.agent` 并丢弃 disposer，于是浏览器打开过的会话在整个进程生命周期内保持活动且无法释放——而持久化拒绝在活动写入者之下删除。`releaseSession` 是唯一的消费者。
- **`WorkspaceRegistry.forgetSession`** 一并丢弃账本槽位与归档集成员身份。与归档不同，它从不查询持久化：调用方正在移除该会话，因此不再列出它的清单是预期结果而非故障。
- **浏览器先确认。** 对话框写明会话名称、说明子代理会话随之删除而 fork 会保留，并指出该操作无法在应用内撤销。拒绝信息留在对话框上供操作者处理，而不像非破坏性行操作那样仅写入控制台。

覆盖范围：持久化移除、缺失报告、活动写入者下的拒绝、保留位置、清理窗口，以及 fork 存活特性；确认门、拒绝呈现，以及工作中行上被禁用的操作。

## Alternatives considered

- **不带保留期的永久移除。** 使用者的原话是「彻底移除」，这也是最初提供的首选项。改为保留是因为全新的删除代码恰恰是 bug 无法挽回的地方，而重命名进 `_trash` 几乎没有成本，却让首个版本中的任何失误都能手工恢复。
- **递归删除会话目录。** 否决：`rm -rf` 没有原子点。中途失败会留下看起来仍像会话、却已无法解析的目录，比重命名的任一结果都糟。
- **拒绝删除活动会话，而不是释放它。** 在发现 api 层会让每个打开过的会话永久保持活动之后否决：该规则将意味着会话在打开它的那次运行中永远无法被删除。
- **保留子代理子会话。** 否决：父会话消失后没有界面列出它们，它们会不可达地堆积。对话框选择说明级联而非隐藏它。
- **GUI 的「清空回收站」控件。** 推迟而非否决。基于时间的清理不需要任何界面即可满足「单独清理」；若将来需要按需回收保留空间，再加一个显式控件也很小。
- **随父会话删除 fork 子会话。** 依据证据否决：fork 子会话是完整、可独立使用的会话，侧边栏将其列为顶层行，且其日志不依赖父会话。

## Consequences

- 删除是 harness 中第一个销毁持久化会话数据的操作。保留窗口正是让它可以安全发布的原因，因此把 `trashRetentionDays` 缩短为 `0` 会移除这道安全网，应当是有意识的部署选择。
- 被保留的字节在窗口期内仍占用磁盘。需要立即回收空间的操作者必须手工清空 `_trash`。
- `ApiSessionAgentController` 持有拆卸能力改变了 Agent 的生命周期：释放会话现在会真正解开其作用域世界。未来任何 `releaseSession` 的消费者都继承这一点。
- 当另一进程持有写锁时删除会话，只会在本进程的 tracker 内被拒绝；跨进程竞争表现为重命名自身的文件系统错误，而非带类型的拒绝。
